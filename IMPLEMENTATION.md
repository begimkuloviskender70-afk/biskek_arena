# Bishkek Arena — первая версия

Русский интерфейс. Время матчей — Asia/Bishkek (UTC+6).

## Реализовано

Steam OpenID с проверкой подписи у Steam, одноразовым состоянием, защитой от повторов и серверными сессиями. Профили, команды по пять игроков, капитаны, секретные приглашения, открытые вызовы BO1, принятие и отмена, проверка расписания, фиксация состава матча. Необязательная загрузка FACEIT уровня и ELO по подтверждённому SteamID. Реальные данные хранятся в D1. Демоданные изолированы в браузере.

Для ограниченного диапазона FACEIT нужны известные уровни всех пяти игроков, обновлённые не более суток назад. Полный диапазон 1–10 допускает неизвестный уровень. Между матчами одной команды оставляется минимум три часа. Состав заблокирован до отмены ближайшего вызова либо истечения его временного окна.

## Границы текущей версии

Игровые серверы не арендованы. Нет автоматического запуска игры, veto, счёта, демо, результатов, рейтингов, турниров, платежей и панели судьи. Принятый вызов означает договорённость, а не назначенный сервер. FACEIT OAuth пока не реализован: данные загружаются через Data API. Капитан пока не может передавать управление/покидать команду.

Закрытая публикация Sites доступна владельцу. Контроль доступа Sites сохраняется поверх Steam-входа. Для приглашения других игроков аудиторию надо настроить отдельно. Полный вход с человеческим Steam-аккаунтом требует прохождения владельцем; автотесты проверяют протокол с имитацией ответов Steam.

## Технологии и запуск

Vinext/React/TypeScript, Cloudflare Workers и D1 (SQLite). PostgreSQL из раннего обсуждения в этой версии не используется. Исходники доменных правил — lib/league.ts, вход — lib/auth.ts, lib/steam-openid.ts. Миграции Drizzle лежат в drizzle/.

Рекомендуется Node.js 24 LTS. Установка: `npm run install:ci`. Затем `npm run build`. Применение локальной миграции:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_marvelous_warpath.sql
npm run dev
```

Миграцию применять один раз. Локальная и опубликованная базы раздельны. Таблицы не создаются при обработке HTTP-запросов.

Steam OpenID не требует API key. Без ключа профиля новый игрок получает нейтральный ник и меняет его сам. Необязательные секреты STEAM_WEB_API_KEY и FACEIT_API_KEY задаются в окружении Sites; локально — в игнорируемом .dev.vars. Секреты не коммитить. Origin callback жёстко связан с текущим доменом; при смене домена обновить allowlist в lib/steam-openid.ts и повторить проверки.

## Проверки

```sh
node --experimental-transform-types --test tests/league.test.mjs tests/auth-openid.test.mjs tests/auth-session.test.mjs
npx tsc --noEmit
npm run build
```

23 теста: OpenID, CSRF, cookie, срок сессии, replay, проверка SteamID FACEIT, права капитана, принятие вызова только один раз, составы, приглашения, уровни и время. Лента сохраняет действующий вызов и его команду, даже если появились более новые отменённые записи. Тестовые записи не попадают в опубликованную базу.

Реальный режим обновляет данные при возвращении на вкладку и каждые 30 секунд. После выхода клиент заново загружает гостевое состояние, поэтому секретный код приглашения капитана не остаётся в интерфейсе.

## Следующая итерация

Арендовать тестовый CS2-сервер с MatchZy и измерить пинг из Бишкека. Добавить контроллер с защищённым HTTP API: Workers не могут управлять RCON по raw TCP. Затем реализовать резервирование сервера, готовность игроков, выбор карты, сохранение событий с повторной доставкой, результат и демо. До открытой беты добавить эксплуатационные лимиты, модерацию, правила отмен и восстановление после сбоев.

FACEIT-профиль не предоставляет FACEIT Anti-Cheat и не позволяет начислять FACEIT ELO за матчи на отдельном сервере.
